# 像素画规范（可检验）

> 目的：把「好看」拆成一串能测量的数字，让每次出图都能被自动判死，而不是靠事后互相说「有点丑」。

---

## 一、为什么 AI 画的 16×16 会难看

不是审美不行，是**默认行为不对**。没有参考时，AI 画像素画会稳定地犯三个错：

| 默认行为 | 为什么致命 | 指标 |
|---|---|---|
| 居中 + 左右对称 | 对称 = 贴纸感。人眼一秒识破 | 对称度 86%，vanilla 是 41% |
| 把画布填满 | 原版物品只占 ~46% 面积，留白就是体积 | 不透明像素 174，vanilla 是 119 |
| 大面积亮色 | 原版最亮色只有 1 个像素（n=1），是**高光点**不是面 | 亮部占比 8%，vanilla 是 6.7% 且集中在 2 个像素 |

我第一次画的版本，三项全挂。这三项**不用眼睛就能测出来** —— 这就是改进的入口。

## 二、正确做法：不要「创作」，要「派生 + 规则」

贴原版的 mod，贴图的正解不是画一张新图，而是**拿原版那张图，加上一条规则去改**。

原因：玩家已经认得 `rotten_flesh` 的轮廓。你换轮廓 = 突兀（破铁律 2）；你只换颜色 = 「同一个东西，被洗过了」，这正是我们要的叙事。

```
1. 取参考   从客户端 jar 里把同类物品的贴图提出来（tools/inspect_ref.py 会打印色板和结构图）
2. 拆结构   按亮度排序成「色阶索引」，形与明暗结构原样保留
3. 规则重映射 只改色板：去饱和 42%、顶部三阶加冷色（湿的暗示）
4. 加叙事   在最暗的缝隙里点水珠（程序选点，可复现）
```

产物：`gen_texture.py`。整个过程没有一句话是「我觉得这里应该亮一点」。

## 三、五条硬指标（实测 vanilla 得出）

| 指标 | 合格线 | vanilla 参考 |
|---|---|---|
| 颜色数 | ≤ 12 | 5–11 |
| 不透明像素 | 100–135 | 108–128 |
| 左右对称度 | ≤ 55% | rotten_flesh 40.6% / leather 75.8% |
| 最亮两阶占比 | ≤ 8% | 6.7%（且集中在极少数像素） |
| 最暗两阶占比 | ≥ 22% | 29.4% |

`tools/sprite_check.py <png>` 逐条打 OK / FAIL。

> 注：`leather.png` 自己就超了对称度（75.8%），所以这是「经验线」不是「物理定律」——
> 但对**第一次画**的 AI 来说，这几条线能挡掉 80% 的失败。

## 四、验收方式

1. `sprite_check.py` 全绿
2. `contact_sheet.py` 生成对照图：vanilla 参考 / 旧版 / 新版并排，**6 倍最近邻放大 + 棋盘底**
3. 看对照图：新版能不能一眼被认成「同一个东西的变体」？不能就是改过头了
4. 进游戏看 1:1 尺寸 —— 16×16 在方块上比在 6 倍图上难看得多

## 五、什么时候该真的手画

派生法只适用于「原版物品的变体」。碰到这些情况必须手画：

- 全新的方块 / 生物 / 装备
- 需要多面 UV 的 3D 模型贴图（Blockbench + 多视角）
- 动画帧序列（`.mcmeta` + 逐帧）

那时候的正确路径是：**Blender 定体积 → 正交渲染 → 像素化 → Blockbench 里做 box UV**，而不是直接在 16×16 里抠。

## 六、下次给 AI 的输入怎么写

丢一句「画个洗净的腐肉」→ 得到贴纸。
丢一句「照 `tools/ref/rotten_flesh.png` 改，去饱和、加冷水感、保持轮廓和明暗结构」→ 得到能用的东西。

**一张参考图胜过十句形容词。** 这条对任何图像任务都成立。
